# Verificaciones manuales — `fase-1a-infraestructura-y-auth`

Criterios que no se pueden verificar en local ni en CI sin la cuenta real de AWS (`us-east-1`). Se ejecutan durante
y tras el primer despliegue siguiendo [docs/guia-de-desarrollo.md](../../../docs/guia-de-desarrollo.md), registrando
fecha y evidencia real (sin incluir nunca ID de cuenta, ARNs reales, correos, tokens ni datos personales en Git).

## Procedimiento y registro de verificación (primer despliegue en `prod`)

- 2.3: Respuestas reales de API Gateway HTTP API v2 en `prod` (sin token, ID token, `/health/ready` sin firma SigV4, throttling 429 y timeout de integración) comparadas contra `openapi.yaml` y `backend/openapi.json` (si difieren, actualizar el contrato en la misma tarea); además verificar que el `requestId` real entregado por API Gateway cumple la expresión regular `[A-Za-z0-9._=-]{1,128}` para que `RequestLogMiddleware` preserve la correlación en lugar de caer a un UUID4 · Estado: pendiente del primer despliegue real en `us-east-1`.
- 2.4: Comprobar en `/aws/lambda/monitorglucosa-api` y `/aws/apigateway/monitorglucosa` tras una petición real que `request_id` coincide exactamente con `requestId` de API Gateway (cumpliendo `[A-Za-z0-9._=-]{1,128}`) y que las líneas JSON no contienen cabeceras, IP, query strings ni tokens · Estado: pendiente del primer despliegue real en `us-east-1`.
- 4.2: Confirmar el alta administrativa del usuario propietario (`aws_cognito_user.owner`), recepción de contraseña temporal por correo electrónico (sin SMS), primer inicio de sesión en Cognito Hosted UI y configuración obligatoria de MFA TOTP antes de emitir tokens · Estado: pendiente del primer despliegue real en `us-east-1`.
- 4.5: Ejecutar un script local de un solo uso contra la URL real de `api_endpoint` verificando que (a) un JWT expirado y un JWT de otro User Pool reciben 401 de API Gateway sin invocar la Lambda (comprobado en logs de Lambda) y (b) un ID token es rechazado por la exigencia del ámbito `openid` · Estado: pendiente del primer despliegue real en `us-east-1`.
- 5.3: Verificación bloqueante de ADR 0007 (D3) en el primer despliegue: confirmar que RDS Data API (`scripts/db_bootstrap.py`) acepta el secreto gestionado por RDS (`rds!cluster-...`), ejecuta `scripts/sql/bootstrap.sql` (bloque `DO $$ ... $$`) como una sola sentencia y valida `scram-sha-256` en PostgreSQL 16; confirmar que `mg_api` y `mg_migrator` conectan por TLS + IAM · Estado: pendiente del primer despliegue real en `us-east-1`.
- 5.4: Tras 300 s sin peticiones ni actividad administrativa, confirmar en CloudWatch Metrics (`AWS/RDS ServerlessDatabaseCapacity` sobre la instancia writer) que la capacidad desciende a 0 ACU y permanece en pausa sin llamadas periódicas · Estado: pendiente del primer despliegue real en `us-east-1`.
- 6.3: Enviar una ráfaga de 30 peticiones rápidas a `GET /health` contra `api_endpoint` y comprobar que API Gateway devuelve al menos un HTTP 429 sin invocar la Lambda · Estado: pendiente del primer despliegue real en `us-east-1`.
- 7.3: Verificar en el primer merge a `main` que `deploy.yml` ejecuta `build`, queda detenido en `deploy` esperando aprobación manual de `ldordellygithub` en el entorno `prod` (`G-2` ya activada en GitHub el 2026-11-24) y solo aplica Terraform tras la aprobación · Estado: entorno `prod` con `required_reviewers` verificado el 2026-11-24; ejecución en vivo pendiente del primer despliegue real.
- 8.3: Confirmar recepción de correo de AWS Budgets para los avisos al 80 % (US$16) y al 100 % (US$20) del presupuesto mensual de US$20 (verificable con una prueba temporal de umbral bajo si el gasto del primer mes queda cerca de US$2,75) · Estado: pendiente del primer despliegue real en `us-east-1`.
- 8.4: Confirmar la suscripción de correo del tema SNS `monitorglucosa-alarms` y ejecutar `aws cloudwatch set-alarm-state --alarm-name ... --state-value ALARM --state-reason "Prueba manual fase-1a"` sobre las 4 alarmas (`api-errors`, `migrator-errors`, `apigateway-5xx`, `aurora-not-paused`), verificando recepción de los 4 correos · Estado: pendiente del primer despliegue real en `us-east-1`.
- NFR-2: Medir con 100 peticiones en caliente que `GET /health` y `GET /api/v1/me` cumplen p95 inferior a 500 ms, y tras más de 24 h con Aurora en pausa comprobar que `/health/ready` alcanza 200 en 60 s o menos sumando reintentos (con cada petición individual por debajo de 30 s) · Estado: pendiente del primer despliegue real en `us-east-1`.
- NFR-3: Verificación de ADR 0011: confirmar que todos los recursos desplegados residen en `us-east-1` y contrastar la factura real del primer mes completo contra la estimación de diseño (alrededor de US$2,75/mes y siempre por debajo de US$20/mes) · Estado: pendiente del primer mes en producción en `us-east-1`.
- NFR-5: Verificación de ADR 0008 (D4): inspeccionar el log público del primer despliegue en GitHub Actions y confirmar ausencia total de ID de cuenta AWS, ARNs, nombre del bucket de estado, correo del propietario, tokens o secretos; confirmar también en ese primer apply que IAM acepta `cognito-idp:CreateUserPool` y `aws_ecr_repository_policy.api` al crear las Lambdas · Estado: pendiente del primer despliegue real en `us-east-1`.
- NFR-6: Contraste final en `prod` de los códigos HTTP y cuerpos reales emitidos por API Gateway HTTP API v2 frente a `openapi.yaml`, `backend/openapi.json` y `docs/api/README.md`, ajustando el contrato si algún detalle del gateway difiere de lo documentado · Estado: pendiente del primer despliegue real en `us-east-1`.
